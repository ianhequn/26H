# 今日优化复盘：从 30 FPS 到约 60 FPS

## 1. 起点不是“换一个更小模型”

原始 YOLOv5s-320 KModel 检测效果好，但推理约 34 ms，整机约 30 FPS。
真正目标是让视觉模块适合小车实时控制，同时保留多钢球检测能力。

因此先把约束写清楚：

- K230 CanMV 板端运行
- 有效工作区域主要在画面中央
- 每帧最多输出 5 个球
- 坐标需要通过 USB 调试串口发送
- 目标帧率约 60 FPS
- 不能只看单球效果，还要关注多球漏检

这一步的核心思路是：先优化系统输入和任务边界，再决定模型大小。

## 2. 用 ROI 换取有效算力

摄像头为 `1920×1080`，但目标主要出现在中央区域。部署链路改为：

```text
1920×1080 sensor
-> center 1080×1080 ROI
-> resize to 224×224 RGB
-> YOLOv5n
```

ROI 并不是随意降低清晰度，而是删除控制系统不使用的边缘像素，让
`224×224` 的每个输入像素更多地覆盖有效区域。检测中心随后再映射回
`1920×1080` 传感器坐标。

## 3. 先建立可比较的 baseline

训练 YOLOv5n-224 后得到 baseline PT：

```text
mAP50:    0.8476
mAP50-95: 0.3594
```

这说明 224 输入具备工程可行性，但仅凭 PT 指标不能判断板端效果。精度可能在
PT、ONNX、KModel、板端预处理中的任意一层下降。

## 4. 统一 PT、ONNX、KModel 评测

旧测试脚本存在输入尺寸、类别、NMS 和坐标格式不统一的风险，因此建立一个统一
评测器，让三个后端共享：

- 同一验证集，包括空标签背景图
- 同一 RGB 和 `224×224` 预处理
- 同一输出解码和 NMS
- 同一置信度、IoU 和 `max_det=5`
- 同一 AP、误检、漏检和中心误差计算

结果显示 PT 与 ONNX 几乎逐元素一致，而旧 KModel 出现可测量下降。由此排除
“ONNX 导出是主要问题”，把排查重点移动到量化和转换。

## 5. 找到量化校准集的真实问题

旧脚本按文件名排序后直接取前 50 张训练图片：

```powershell
Get-ChildItem $datasetImages -File | Select-Object -First 50
```

由于 `negative_hard_*` 排在前面，最终校准集为：

```text
无球图片：50
有球图片：0
```

PTQ 需要通过代表性图片观察激活分布。全负样本校准意味着量化器没有观察到钢球、
强反光和多球靠近时的激活峰值，导致 KModel 的置信度分布发生偏移。

新的 100 张校准集覆盖：

```text
0 球：20
1 球： 4
3 球： 4
4 球：71
5 球： 1
```

同时按亮度、对比度和清晰度选择有差异的样本。它不是人为制造完全均衡分布，而是
在现有数据约束下保证正负样本和主要成像条件都被量化器看到。

## 6. 用教师模型指导小模型

YOLOv5s-320 的效果好，因此使用它的 PT checkpoint 作为 teacher，以
YOLOv5n-224 baseline PT 作为 student。

训练时 teacher 和 student 都接收 `224×224` 输入，使 Detect 层网格一致：

```text
P3: [B, 3, 28, 28, 6]
P4: [B, 3, 14, 14, 6]
P5: [B, 3,  7,  7, 6]
```

总损失为：

```text
L_total = L_YOLO + lambda * L_KD
L_KD = L_objectness + 0.5 L_box + 0.25 L_class
```

人工标签仍是主要监督信号，teacher 提供的是检测位置、框回归和置信度分布的软指导。
teacher 只参与训练，部署时仍然只有 YOLOv5n，因此不会降低板端帧率。

## 7. 失败实验如何推动参数调整

第一次 smoke test 使用：

```text
kd_weight = 0.15
```

加权后的蒸馏损失大于监督损失，第一轮验证指标下降。处理方式不是继续盲训，而是
比较两类 loss 的量级，确认 teacher 信号压过了人工标签。

最终改为：

```text
kd_weight = 0.04
temperature = 2.0
object threshold = 0.02
KD warmup = 5 epochs
epochs = 40
```

warmup 让蒸馏权重在前五个 epoch 逐步增加，先让 student 学会基本检测，再接受
teacher 的细粒度约束。

## 8. 最终结果

| Model | mAP50 | mAP50-95 | Deploy FP | Deploy FN |
|---|---:|---:|---:|---:|
| Baseline KModel | 0.8287 | 0.3526 | 42 | 33 |
| Distilled KModel | 0.8520 | 0.3726 | 35 | 23 |

新的 KModel 相对蒸馏 PT 的 mAP50 下降约 `0.0018`，说明量化精度基本得到保留。
CanMV 实机演示约 60 FPS，并能同时通过 USB 输出最多 5 个钢球中心坐标。

## 9. 这次优化形成的通用方法

```text
明确系统约束
-> 建立小模型 baseline
-> 统一不同后端评测
-> 定位精度下降层级
-> 检查数据与量化校准
-> 引入 teacher 但保持人工标签主导
-> 用小实验确定 loss 量级
-> 重新导出、量化、离线验证
-> 板端验证帧率和通信闭环
```

真正有价值的不是某一个参数，而是把“模型不好”拆成可验证的工程问题，并为每一层
建立证据。

## 10. 仍需补完的实验

最重要的下一步是四组消融：

```text
A: baseline PT  + 旧校准集
B: baseline PT  + 平衡校准集
C: distilled PT + 旧校准集
D: distilled PT + 平衡校准集
```

当前已有 A 和 D。补齐 B、C 后，可以分别量化知识蒸馏与校准集修复贡献了多少。
此外还应增加独立视频测试集、端到端控制延迟和板端自动回归测试。
